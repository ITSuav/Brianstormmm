# 无人机物资配送路线规划平台方案

## 1. 项目背景

无人机物资运送的路线规划。

场景设定在香港，配送站点同时覆盖市区和山区，因此路线规划会面临比普通地面配送更复杂的问题，包括:

- 市区高楼密集，飞行限制多，环境动态变化快
- 山区地形复杂，风力、海拔、信号等因素影响较大
- 不同站点之间的距离、载重、电量消耗、紧急程度不同
- 无人机需要在安全、效率、成本之间取得平衡

构建一个 Web 端平台，用于完成无人机配送任务的可视化管理、智能路线规划、模拟调度 与结果分析。

---

## 2. 项目目标

### 2.1 业务目标

- 提高物资配送效率
- 降低人工调度成本
- 缩短紧急物资响应时间
- 提升山区和复杂城区的配送可达性

### 2.2 技术目标

- 构建一个可视化 Web 平台
- 实现基础的无人机路线规划算法
- 支持多站点、多任务、多约束条件下的路径计算
- 展示任务调度、路径结果和关键指标

### 2.3 展示目标

- 页面清晰、逻辑完整、适合比赛演示
- 能通过地图、图表、任务看板直观展示效果
- 能对比“人工调度”与“智能调度”的差异

### 2.4 团队协作目标

- 六个人分工明确
- 前后端、算法、数据、产品、汇报同步推进
- 在有限时间内做出一个可演示、可讲述、可答辩的成果

---

## 3. 我们要解决的核心问题

无人机配送不是简单的“从 A 飞到 B”，而是一个带有多重约束的路径优化问题。平台需要 重点解决以下几类问题:

### 3.1 路径规划问题

- 怎样从起点到终点选择更优路线
- 怎样避开禁飞区、高楼密集区或高风险区域
- 怎样兼顾飞行距离、时间、电量消耗和安全性

### 3.2 多任务调度问题

- 多架无人机如何分配多个配送任务
- 紧急任务是否需要插队
- 不同任务优先级如何影响整体调度

### 3.3 场景差异问题

- 市区更关注障碍密度、空域限制、路径绕行
- 山区更关注地形起伏、续航能力、天气和通信稳定性

### 3.4 管理可视化问题

- 企业管理者如何看到当前任务状态
- 调度人员如何快速调整异常任务
- 平台如何展示优化前后效率提升

---

## 4. 平台整体定位

我们要做的是一个“无人机配送智能调度与路线规划平台”。

平台建议分为 4 个核心模块:

### 4.1 地图与站点管理模块

- 在地图上展示香港市区与山区站点
- 标注仓库、配送点、中转点
- 展示禁飞区、高风险区域、山地区域等信息

### 4.2 任务管理模块

- 创建配送任务
- 设置起点、终点、物资类型、重量、时限、优先级
- 查看任务状态: 待分配、配送中、已完成、异常

### 4.3 智能规划模块

- 根据任务自动生成推荐路线
- 支持单任务最短路径和多任务调度
- 结合约束条件生成更合理的飞行方案

### 4.4 数据分析与决策展示模块

- 展示总配送时间、平均时长、成功率、能耗估计
- 对比优化前后路径差异
- 展示不同区域任务压力和无人机利用率

## 5. 一步一步怎么做

为了让项目真正落地，建议按照“先讲清问题，再做可演示产品”的思路推进。

### 第一阶段: 明确题目与展示边界

这一阶段的目标不是立刻写代码，而是统一全队认知。

要完成的事情:

- 明确企业痛点到底是什么
- 明确你们比赛更看重“算法创新”还是“平台展示”
- 统一平台场景: 重点做应急物资配送，还是日常多点配送
- 明确最终交付物: 平台 Demo、方案文档、答辩 PPT、演示视频

输出成果:

- 一页问题定义
- 一页目标用户与使用场景
- 一页平台功能范围

### 第二阶段: 设计业务流程

这一阶段要让评委看到“企业怎么用你们的平台”。

建议梳理一条完整业务链:

1. 管理员录入站点信息
2. 调度员创建配送任务
3. 系统读取任务约束条件
4. 算法生成路线与任务分配方案
5. 平台地图展示飞行路径
6. 管理员查看结果并做调整
7. 系统统计任务表现并输出分析报表

输出成果:

- 一张业务流程图
- 一张用户操作流程图
- 一份核心页面草图

### 第三阶段: 定义平台功能

在这个阶段，需要从“想法”收敛到“比赛版本必须做什么”。

建议把功能分为三层:

#### 必做功能

- 地图展示站点与区域
- 创建配送任务
- 输入任务约束条件
- 自动生成路线
- 展示路径结果
- 展示基础数据统计

#### 加分功能

- 多架无人机协同调度
- 紧急任务优先插入
- 风险区域动态绕行
- 优化前后对比分析

#### 可选展示功能

- 任务回放动画
- 大屏数据驾驶舱
- 不同天气场景模拟

### 第四阶段: 搭建技术方案

这一阶段进入实际开发准备。

你们可以采用前后端分离的方式:

- 前端负责页面、地图、图表、交互展示
- 后端负责任务管理、数据接口、调度逻辑调用
- 算法模块负责路线规划和任务分配
- 数据模块负责站点数据、区域数据和测试样本整理

### 第五阶段: 先做最小可用版本

比赛项目最怕做得太大、最后什么都没做完整。因此建议先做 MVP。

MVP 版本建议只保证以下链路跑通:

1. 地图上展示站点
2. 用户输入一个配送任务
3. 系统生成一条推荐路线
4. 页面展示路线和关键指标

只要这条链路能跑通，你们就已经有一个可演示原型。之后再逐步加多任务调度、对比分析和可视化优化。

### 第六阶段: 完善演示与答辩材料

比赛最终比的不只是功能，还包括表达。

这一阶段需要补齐:

- 项目背景与痛点分析
- 解决方案架构图
- 算法思路说明
- 平台界面截图
- 应用价值与落地前景
- 团队分工与开发过程

## 6. 平台应该怎么搭建

## 6.1 推荐技术架构

为了兼顾开发效率和展示效果，建议使用以下技术组合:

### 前端

- `React` 或 `Vue`
- 地图组件可使用 `Mapbox`、`Leaflet` 或高德/天地图方案
- 图表可使用 `ECharts`
- UI 组件库可使用 `Ant Design` 或 `Element Plus`

### 后端

- `Node.js + Express/NestJS`
- 或 `Python + FastAPI`

如果队里 Python 更强，建议优先 `FastAPI`，因为后续算法集成会更自然。

### 算法模块

- 使用 `Python`
- 可先实现基础最短路径算法
- 再逐步加入约束优化、任务优先级、多机调度

### 数据层

- 比赛原型阶段可以先用 `JSON` 或 `SQLite`
- 如果时间充足再接入 `MySQL` 或 `PostgreSQL`

---

## 6.2 推荐系统架构

可以按下面思路设计:

### 前端层

- 地图展示页面
- 任务管理页面
- 数据分析页面
- 系统总览首页

### 服务层

- 用户请求接口
- 任务管理接口
- 路线规划接口
- 数据统计接口

### 算法层

- 单路径规划
- 多任务分配
- 路径评分模型

### 数据层

- 站点数据
- 区域数据
- 任务数据
- 无人机参数数据

---

## 6.3 页面建议

比赛版本建议至少做 4 个页面:

### 1. 首页 / 总览页

- 展示项目介绍
- 展示今日任务数、完成率、平均配送时长等指标
- 展示区域热力或任务分布

### 2. 地图调度页

- 地图展示站点、路径、禁飞区
- 支持任务选择
- 点击后展示推荐路线和飞行信息

### 3. 任务管理页

- 新建任务
- 查看任务列表
- 设置优先级、物资重量、时限

### 4. 数据分析页

- 展示配送效率变化
- 展示优化前后对比
- 展示不同区域任务完成情况

## 7. 算法部分怎么讲

比赛中不一定要求把算法做到特别学术，但一定要讲清楚“为什么这样规划”。

建议按照“由浅入深”的方式设计:

### 7.1 第一层: 基础路径规划

- 根据站点间距离构建图结构
- 用最短路径算法找到推荐路线

适合先快速实现、便于展示。

### 7.2 第二层: 加入约束条件

在基础路径上加入:

- 电量限制
- 载重限制
- 任务时限
- 禁飞区绕行
- 风险区域惩罚

这样平台就能体现“不是最短，而是更合理”。

### 7.3 第三层: 多任务调度

- 多架无人机同时执行任务
- 根据优先级和距离进行任务分配
- 提升总体效率

### 7.4 比赛里怎么表达算法价值

你们不一定非要强调“算法多先进”，而是要强调:

- 规划速度更快
- 路线更安全
- 资源利用率更高
- 对复杂城市场景和山区场景更适配

## 9. 六个人如何协作推进

建议把项目分为 4 个并行小组，但保持每日同步:

### A 组: 产品与汇报

- 成员 1 + 成员 6
- 负责需求梳理、文档、PPT、答辩逻辑

### B 组: 前端展示

- 成员 2 + 成员 3
- 负责 Web 页面、地图、图表、交互

### C 组: 后端服务

- 成员 4
- 负责接口和系统支撑

### D 组: 算法模型

- 成员 5
- 负责路径规划与调度逻辑

协作方式建议:

- 每天固定一次 15 分钟站会
- 先统一数据结构，再分别开发
- 前端先用假数据开发页面
- 后端和算法先定义接口格式
- 最后集中联调和演示彩排

## 11. 比赛展示时怎么讲

你们的讲述逻辑建议按下面顺序展开:

### 11.1 先讲痛点

香港市区高密度建筑和山区复杂地形并存，传统人工调度难以兼顾效率、安全与时效，因此企业在无人机配送中面临复杂路线规划问题。

### 11.2 再讲解决方案

我们构建了一个 Web 端无人机配送智能调度平台，通过地图可视化、任务管理和智能规划 算法，帮助企业更高效地完成复杂场景下的物资运输。

### 11.3 再讲核心亮点

- 城市与山区混合场景
- 路线规划与任务调度结合
- 平台化展示而非单点算法
- 可视化强，适合企业应用和比赛演示

### 11.4 最后讲价值

- 提高配送效率
- 降低调度成本
- 提升紧急响应能力
- 具备未来落地扩展空间

## 12. 现阶段最建议你们优先做的事

如果你们现在刚开始，最优先做的不是把所有功能都写出来，而是先完成这 5 件事:

1. 明确一个清晰场景
   例如: 山区医疗物资应急配送，或者市区与山区混合配送

2. 画出平台结构
   至少明确有哪些页面、页面之间怎么跳转

3. 定义核心数据
   包括站点、任务、无人机、路线结果等数据结构

4. 先做最小 Demo
   实现“输入任务 -> 生成路线 -> 地图展示结果”

5. 同步准备答辩材料
   比赛项目通常不是代码做完再准备 PPT，而是开发和表达同步进行

---

## 13. 总结

这次比赛的关键，不是单纯做一个算法，而是围绕企业痛点，做出一个有业务逻辑、有技术支撑、有展示效果的平台型方案。

对于你们六个人的小组来说，最合理的策略是:

- 用一个明确场景聚焦问题
- 用一个 Web 平台承载解决方案
- 用一个可解释的算法体现技术能力
- 用清晰分工保证推进效率
- 用强表达能力提升比赛呈现效果

一句话概括你们的方向:

> 以香港复杂城市场景为背景，构建一个面向企业无人机物资配送的智能路线规划与调度 Web 平台，实现任务管理、路径优化和可视化决策支持的一体化解决方案。
